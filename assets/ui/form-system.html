The problem

Every path ended in a calendar.

An audit of the site showed that every call to action, on every page, pointed to the same Calendly booking link. There was no form anywhere on the site.

Booking a call is a big ask for a busy contractor who is still deciding. Anyone who wasn't ready to commit to a time slot left without a trace, and the leads who did book showed up with nothing in the CRM: no trade, no city, no Google Business Profile to review before the call.

    What happens on submit
    
One script handles every form.

    
Each form on the site uses the same submit handler. A page only declares which form it is and what it pre-fills; validation, the CRM call and the tracking events come from the system.

  

  

    
1 · Validate
Check in the browser
Required fields, US phone format, email shape, Google Maps URL pattern. Errors appear on blur and again on submit.

    
2 · Send
Create the CRM contact
Upsert by email so repeat visitors don't create duplicates. Tagged with trade and source page, stage New lead.

    
3 · Measure
Fire GA4 events
form_start, form_step and generate_lead, so drop-off is visible by step and by page.

    
4 · Book
Hand off to Calendly
The booking link opens with name, email and trade filled in. The existing schedule_call event still fires.

    Proposed rollout
    
One page first, then the rest.

    
The free-trial page already tracks bookings, so it gives a clean before-and-after. Once the form proves itself there, each next page reuses the same component with different pre-filled values.
